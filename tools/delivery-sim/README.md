# 배송 시뮬레이터 (시연 도구)

시연장에서는 폰을 들고 250m 칸을 넘어 다닐 수 없어서, 이 페이지가 실제 도로 경로를 따라 배송원 위치를 대신 움직입니다.
서비스 기능이 아닙니다. client/ 빌드와 서버 배포에 포함하지 않고, 서버에 시뮬레이터 전용 코드를 넣지 않습니다.

- 지도: Leaflet + OpenStreetMap 타일(무채색), 250m 격자(서버 칸 계산과 같은 식) 40칸
- 경로: OSRM `/route` (기본은 공개 OSRM, 예비로 노트북 OSRM)
- 위치: 1.5초마다와 칸이 바뀔 때 `PUT /api/delivery/location {lat, lng}` (배송원 토큰)
- 후보 표시: `GET /api/delivery/requests/bundle`의 칸을 "후보 출발 칸"으로, 진행자가 찍은 목적지 칸과 이웃 8칸을 "후보 도착 범위"로 칠합니다. 서버는 콜 좌표를 주지 않으므로 콜마다 점을 찍지 않습니다.
- 폰 연결: 로그인한 토큰을 QR(`<배송원 웹 주소>/driver#token=…&sim=1`)로 넘깁니다. 폰에서 따로 로그인하지 않습니다.
- 글꼴: client/와 같은 Paperlogy에서 화면 글자만 남긴 woff2(700·900, 합쳐 약 40KB)를 `src/fonts`에 둡니다.

## 띄우는 방법 1: Vercel 정적 배포 (기본)

`vercel.json`이 빌드와 경로를 정합니다.

| 경로 | 넘기는 곳 | 비고 |
|---|---|---|
| `/api/delivery/*` | `https://setty.cloud/api/delivery/*` | Origin 요청 헤더를 지워 prod CORS 설정을 바꾸지 않습니다. 배송원 API만 엽니다 |
| `/osrm/*` | `https://router.project-osrm.org/*` | 공개 OSRM |

두 경로 모두 `x-vercel-enable-rewrite-caching: 0`으로 리라이트 캐시를 끕니다. 빌드할 때 QR 주소는 `https://setty.cloud`로 고정됩니다.

```bash
cd tools/delivery-sim
npx vercel login
npx vercel deploy          # 미리보기 주소. 확인 뒤 --prod
```
- 레포를 Git으로 연결하지 않고 이 폴더만 CLI로 올립니다. 처음 배포할 때 새 프로젝트를 만들고, Root Directory는 이 폴더 그대로 둡니다.
- 공개 주소가 생기므로 배포는 사람이 직접 합니다.
- prod에 묶음 배송 서버(위치 전송·후보 API)가 배포돼 있어야 위치 전송이 200이 됩니다. 그 전에는 로그인·경로·QR만 됩니다.
- 공개 OSRM은 무료 공용 서버라 요청이 몰리면 느리거나 막힐 수 있습니다. 그럴 때는 방법 2로 바꿉니다.

## 띄우는 방법 2: 노트북 로컬 (예비)

```bash
cd tools/delivery-sim
npm install
./osrm.sh                                   # 노트북 OSRM(서울 car 데이터)
SIM_API_URL=https://setty.cloud SIM_CLIENT_URL=https://setty.cloud npm run dev
```
http://localhost:5180 을 엽니다.
- OSRM은 `~/osrm/seoul.osrm.*`(서울 car, MLD)을 씁니다. 다른 곳에 있으면 `OSRM_DATA_DIR=경로 ./osrm.sh`. 이미지는 데이터를 만든 버전(v26.10.0)으로 고정했습니다. 끌 때 `docker rm -f delivery-sim-osrm`.
- Vite 프록시도 Origin 헤더를 떼므로 서버 CORS 설정은 바꾸지 않아도 됩니다.

## 설정

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `SIM_API_URL` | `http://localhost:8080` | 로컬 실행 때 `/api`를 넘길 서버, 화면 아래 표시 |
| `SIM_CLIENT_URL` | `http://<노트북 LAN IP>:3000` | QR에 담을 배송원 웹 주소. 노트북의 client 개발 서버를 쓸 때는 `npx webpack serve --mode development --no-compress`로 띄워야 SSE가 바로 옵니다 |
| `SIM_OSRM_URL` | `http://localhost:5008` | 로컬 실행 때 `/osrm`을 넘길 OSRM |
| `SIM_AREA` | `37.4945,126.9265,8,5` | 격자 영역: 남쪽 위도, 서쪽 경도, 가로 칸 수, 세로 칸 수(상도3·4동 일대) |

영역을 바꿀 때는 `SIM_AREA` 한 값만 바꿉니다. Vercel에서는 `vercel.json`의 `buildCommand` 앞에 `SIM_AREA=…`를 붙입니다.

## 계정 준비
- 배송원 계정: 동시에 체험할 인원 수만큼. 시뮬레이터 하나에 폰 하나가 짝입니다.
- 판매자·구매자: 격자 영역 안 주소로 가입한 회원. 이들의 주문이 확정되면 출발·도착 칸이 정해진 콜이 생깁니다.
- 체험할 배송원이 진행 중 배차를 한 건 이상 갖고 있어야 "가는 길에 실을 콜"이 뜹니다.

## 진행
1. ① 배송원 연결: 배송원 아이디로 로그인하고, 체험자가 QR을 폰 기본 카메라로 찍습니다.
2. ② 경로 정하기: 지도에서 출발지를 찍습니다. "진행 중 배차 도착 주소 보기"로 내 배차의 도착 주소를 보고 그 근처를 목적지로 찍습니다.
3. ③ 주행: 속도(1배 = 시속 30km)를 고르고 출발을 누릅니다. 후보가 뜬 칸은 진한 파랑, 목적지 3×3은 옅은 파랑으로 칠해지고, 패널에 후보 상품명·배송비가 나옵니다. 같은 때 폰의 "가는 길에 실을 콜"에도 뜹니다.

## 주의
- 로그인 토큰은 시뮬레이터 탭에만 둡니다. 탭을 닫으면 다시 로그인하고 QR을 새로 찍습니다.
- 서버는 진행 중 배차의 실제 도착 칸으로 후보를 고르고, 지도의 도착 범위는 진행자가 찍은 목적지 기준입니다. 목적지는 진행 중 배차 도착 주소 근처로 찍습니다.
- 콜을 보여 줄 칸은 경로가 그 칸 가운데를 지나게 고르고 속도는 1~2배를 씁니다. 칸 모서리만 스치면 그 칸에 1초쯤만 머뭅니다.
- 진행자가 다른 곳에서 같은 배송원으로 다시 로그인하면 이전 토큰이 끊깁니다. 위치 전송이 실패(401)로 바뀌면 다시 로그인하고 QR을 새로 찍습니다.
- 시뮬레이터 창이 가려져도 차는 계속 갑니다. 다만 브라우저가 가려진 탭의 타이머를 늦추므로, 지도 움직임을 보여 줄 때는 탭을 앞에 둡니다.
- 원본 좌표·주소 자료는 이 폴더에 넣지 않습니다. 영역은 경계 숫자만 둡니다.
