# 인증 만료 처리 (#613)

현재 서버 구현 기준이며, 백엔드와 별도 합의를 완료한 문서는 아니다.

| 응답 / 상황 | Android 동작 |
| --- | --- |
| 401 + INVALID_TOKEN | 해당 요청에 사용한 저장 토큰 삭제. 기존 화면의 인증 오류 처리로 로그인 이동 |
| 403 / 다른 오류 코드 | 토큰 유지, 기존 오류 처리 |
| 네트워크 오류 / 서버 오류 | 토큰 유지, 기존 재시도 사용 |

응답 본문은 peekBody로 읽어 호출자도 그대로 읽을 수 있다. 토큰 삭제는 DataStore의 원자적 갱신 안에서 요청 토큰과 현재 토큰이 같을 때만 수행한다. 따라서 이전 요청의 늦은 401이 재로그인한 세션을 삭제하지 않는다. 갱신과 자동 재시도는 수행하지 않는다.

현재 서버는 단일 로그인 토큰이며 Refresh 토큰 및 갱신 API가 없다. 무중단 갱신, 동시 갱신 병합, Refresh 폐기 시연은 서버 지원 이후 구현해야 한다. 로그인 이동 시 기존 내비게이션은 스택을 비우므로 재로그인 후 원래 화면/작성 내용 복원도 별도 작업이다.

## 개발 서버 수동 확인 (미실행)

1. 로그인한 뒤 서버에서 해당 토큰을 만료/무효화한다.
2. 인증 API를 호출하고 로그인 화면 이동 및 저장 토큰 삭제를 확인한다.
3. 재실행 후 이전 토큰이 Authorization에 포함되지 않는지 확인한다.
4. 오프라인 및 403/500 응답에서는 저장 토큰이 유지되는지 확인한다.
5. 이전 토큰 요청을 지연시킨 상태에서 재로그인하고 이전 401을 수신해 새 토큰이 유지되는지 확인한다.

서버 근거: MemberAuthInterceptor, InvalidTokenResponse, ErrorCode.INVALID_TOKEN (401).
