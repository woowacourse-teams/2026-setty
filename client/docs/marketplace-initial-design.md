# 미니마켓 프론트 초기 설계

## 목적과 기준

- GitHub Issue #142 범위에서 중고 가구·가전을 넘겨보고, 상세를 확인하고, 익명 쪽지를 보낼 수 있는 모바일 우선 프론트엔드를 만든다.
- 기존 회의 자료는 기준으로 사용하지 않는다. 구현 기준은 Issue #142, 이번 작업에서 확정한 계획, `screens/`의 PNG 10장과 `FLOW.md`, 전달받은 프로토타입 API 계약 순이다.
- 서버, 배포, 루트 문서와 기존 flow 코드는 수정하지 않는다. 기존 SETTY 기능은 삭제하지 않고 앱 라우터에서만 연결을 끊는다.

## 라우트와 화면

| 경로                           | 화면                         | 인증   | 주요 API                                      |
| ------------------------------ | ---------------------------- | ------ | --------------------------------------------- |
| `/`                            | 스와이프 홈                  | 불필요 | `GET /api/listings`                           |
| `/listings/:listingId`         | 매물 상세 전체 화면 오버레이 | 불필요 | `GET /api/listings/{listingId}`               |
| `/listings/:listingId/message` | 익명 쪽지 작성 오버레이      | 불필요 | `POST /api/listings/{listingId}/messages`     |
| `/inbox`                       | 내 매물에 도착한 쪽지함      | 필요   | 판매자 페이지 + 매물별 쪽지 조회              |
| `/mine`                        | 내 매물                      | 필요   | `GET /api/me/seller-page`                     |
| `/mine/new`                    | 매물 등록 오버레이           | 필요   | `POST /api/listings`                          |
| `/mine/:listingId/edit`        | 매물 수정 오버레이           | 필요   | 상세 조회 + `PATCH /api/listings/{listingId}` |

- 인증이 필요한 경로에서 `401`을 받으면 `08-auth.png` 형태의 로그인 오버레이를 연다. 로그인 성공 후 중단했던 조회를 다시 수행하고 원래 경로를 유지한다.
- 등록·수정·삭제처럼 상태를 바꾸는 요청이 `401`로 실패하면 자동 재전송하지 않는다. 로그인 후 사용자가 다시 제출한다.
- 기존 예상 견적·배차·운영자 URL은 새 앱 라우터에 등록하지 않고 404 화면으로 보낸다.

## 화면 동작

### 홈과 상세

- `01-swipe.png`, `09-swipe-drag.png`, `10-deck-empty.png`를 414×892 모바일 기준으로 재현한다.
- 왼쪽으로 90px 이상 드래그하거나 ✕ 버튼을 누르면 현재 카드를 소비하고 다음 카드로 이동한다.
- 오른쪽으로 90px 이상 드래그하거나 `상세 보기` 버튼을 누르면 현재 카드를 소비하고 상세로 이동한다. 상세를 닫으면 다음 카드가 보인다.
- 카드를 탭해 상세로 들어가면 카드를 소비하지 않으며, 닫을 때 같은 카드로 돌아온다.
- 되돌리기는 마지막으로 소비한 카드 한 장을 복원한다. 덱 소진 뒤 `다시 보기`는 목록을 다시 조회하고 첫 카드부터 시작한다.
- 홈 카드는 대표 사진, 제목, 픽업 가능 시간, 운반 도움 여부만 표시한다.
- 상세 사진은 `displayOrder` 오름차순으로 표시한다. 설명의 `http://` 또는 `https://` URL만 새 탭 링크로 만들고 `noopener noreferrer`를 적용한다.

### 쪽지함과 내 매물

- 구매 쪽지는 로그인 없이 보낸다. 성공하면 토스트를 보여주고 진입 전 화면으로 돌아가며, 발신자 화면의 쪽지함에는 별도로 저장하지 않는다.
- 쪽지함은 판매자 페이지에서 내 매물을 조회한 뒤 각 매물의 쪽지를 병렬 조회하고, 매물 제목·썸네일을 결합해 최신 작성순으로 표시한다.
- 발신자 정보는 수집하지 않으므로 모든 항목을 `익명 문의`로 표시한다. 답장, 읽음 상태와 배지는 제공하지 않는다.
- 내 매물은 등록, 텍스트 필드 수정, 삭제와 로그아웃을 제공한다. 수정 화면에서는 기존 사진을 읽기 전용으로 보여주며 사진 교체는 제공하지 않는다.
- 삭제는 별도 비밀번호 재확인 없이 확인 대화상자를 거친다.

## 디자인 적용 범위

- marketplace flow 내부 CSS Modules에 주황 그라데이션, 크림색 배경, 갈색 텍스트와 최대 414px 셸을 둔다. iOS 상태바는 그리지 않고 safe area만 반영한다.
- 아이콘과 로고는 CSS 또는 인라인 SVG로 재현한다. 새 디자인 때문에 외부 UI·아이콘·폰트 의존성을 추가하지 않는다.
- API에 없는 가격, 층·엘리베이터, 가구 한마디, 이상형, 태그는 제거한다.
- 찜 탭, 하트 버튼, 찜 수와 찜 배지는 제거한다. 헤더는 홈, 내 매물, 쪽지함 진입만 제공한다.
- 실제 사진은 API의 이미지 URL을 사용한다. 별도 당근 링크 필드는 만들지 않으며 설명 본문의 URL만 링크로 처리한다.

## API와 데이터 흐름

- marketplace 전용 클라이언트는 `API_ORIGIN`을 사용하고 모든 요청에 `credentials: "include"`를 적용한다.
- JSON 요청에는 `Accept: application/json`과 `Content-Type: application/json`을 사용한다. multipart 등록은 브라우저가 boundary를 만들도록 `Content-Type`을 직접 설정하지 않는다.
- 로그인은 `POST /api/auth/login` 하나만 호출한다. 휴대폰 번호는 숫자만 남겨 10~11자리로 보내고, 비밀번호는 숫자 4자리만 허용한다. 미등록 번호는 같은 요청에서 계정을 생성한다.
- 등록은 `request` JSON Blob과 `images` 1~5개를 multipart로 전송한다. 이미지 형식은 JPEG, PNG, WebP이며 전체 25MB 이하다.
- 수정은 제목, 설명, 픽업 가능 시간, 운반 도움 여부 중 변경된 필드만 JSON PATCH로 전송한다.
- `204`는 본문 없이 성공으로 처리한다. 서버 오류 JSON의 `code`, `message`, `fieldErrors`를 보존하며 네트워크 오류는 HTTP 상태 `0`인 전용 오류로 구분한다.

## 상태와 완료 기준

- 목록, 상세, 내 매물, 쪽지함에는 로딩, 빈 상태, 재시도 가능한 일반 오류를 둔다.
- `401` 로그인 필요, `403` 권한 없음, `404` 삭제되었거나 없는 매물, `413` 이미지 용량 초과, `415` 이미지 형식 오류를 구분해 안내한다.
- 라우팅, 스와이프 임계값과 복귀 규칙, 인증 후 복귀, multipart 등록, 수정·삭제, 익명 쪽지, 쪽지 병합 정렬과 안전한 URL 링크를 자동 테스트한다.
- `npm run lint`, `npm run typecheck`, `npm run test:ci`, `npm run build`를 통과한다.
- 프로토타입 서버 계약과 세션 CORS가 준비되기 전에는 API 모킹 테스트와 브라우저의 로딩·오류 레이아웃까지만 검증한다. 실제 데이터 통합 QA는 백엔드 준비 후 진행한다.
