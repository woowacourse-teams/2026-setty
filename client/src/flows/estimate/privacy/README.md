# 예상 견적 개인정보 FE 경계

Issue #12의 예상 견적 흐름에만 적용한다. 배차 요청은 별도 입력·동의·보관 정책을 확정해야 한다.

## FE가 보장하는 것

- 처리 주체·목적·입력 항목·보유 기간·철회·삭제·문의 방법을 `/estimate/privacy`에서 안내한다.
- 요청 화면에서 `(필수) 개인정보 수집·이용 동의`를 체크하지 않으면 요청을 전송하지 않는다.
- `보기`로 여는 동의 안내 화면(`PrivacyConsentNoticeScreen`)에서 `/estimate/privacy`의 처리 안내 전문과
  같은 항목을 안내한다. 처리 목적, 사용자 입력 항목, 요청 처리 중 생성·저장되는 정보, 보유·이용 기간,
  동의 거부, 철회·삭제 요청과 파기, 처리 주체, 문의, 안내문 적용일·버전이다.
- 안내 화면과 전문 페이지는 모두 `estimatePrivacyPolicy.ts` 한곳의 값을 그대로 쓴다.
- 같은 안내를 배차 동의 화면도 쓴다. 문구를 바꾸면 `client/src/flows/dispatch/PRIVACY.md`의 값도 함께 맞춘다.

## 현재 상태

동의 UI는 화면에만 있다. server `CreateEstimateRequestRequest`에 `privacyConsent`·`privacyPolicyVersion`
필드가 없어 FE도 동의 여부와 안내문 버전을 보내지 않는다.
동의 증적을 실제로 남기려면 아래 BE·운영 항목과 계약을 함께 확정해야 한다.

## BE·운영이 보장해야 하는 것

- `ESTIMATE_NOTIFIED` 안내 완료 시점부터 30일 후 입력값·동의 증적·요청 처리·운영 기록 중 개인을 식별할 수 있는 정보를 삭제한다.
- 철회·삭제 요청을 수동으로 확인·처리하고 개인정보가 아닌 처리 증적을 남긴다.
- 삭제 후에는 특정 개인을 식별할 수 없는 통계만 보관한다.
- 요청·응답·오류 로그에 이름·연락처를 남기지 않는다.

## 실제 사용자 DEV 접수 전 남은 차단 조건

- `setty@example.com`을 실제로 수신·처리할 수 있는 팀 문의 채널로 바꾼다.
- 오래 `PENDING_REVIEW`에 머무는 미완료 요청의 최대 보관 기간을 팀이 확정한다.
- 동의 수집 방식·증적 저장과 삭제 자동화, 수동 철회 절차를 확정하고 통합 테스트한다.
- 운영자 API 인증·접근 보호와 DEV HTTPS·CORS·세션 정책을 확인한다.
- 배포 환경의 위탁·하부 처리 내용을 안내문에 반영한다.

이 파일의 FE 완료는 실제 개인정보 접수 준비 전체가 완료됐다는 뜻이 아니다.
