# 배차 개인정보 FE 경계

배차 요청 흐름에만 적용한다. 예상 견적은 `client/src/flows/estimate/privacy/README.md`의 별도 안내와 정책 값을 쓴다.

## FE가 보장하는 것

- 구매자 요청·판매자 입력 화면의 `(필수) 개인정보 수집·이용 동의`를 체크하지 않으면 요청을 전송하지 않는다.
- `보기`로 여는 동의 안내 화면(`screens/PrivacyConsentNoticeScreen.tsx`)에서 처리 주체, 수집 항목,
  요청 처리 중 생성·저장되는 정보, 이용 목적, 보유·이용 기간, 동의 거부 결과, 철회·삭제와 파기,
  문의 채널, 안내문 적용일·버전을 안내한다.
- 안내 문구의 값은 `model/dispatchPrivacyPolicy.ts` 한곳에서 가져온다. 화면과 문구 파일에서 정책을 새로 만들지 않는다.

## 값의 출처

- 처리 주체·문의 채널·철회·삭제·잔존 데이터 안내: DEC-020의 견적 FE 적용안을 배차 안내에도 같은 문장으로 쓴다.
- 수집 항목·이용 목적·보유 기간: 배차 시안 값을 그대로 둔다. DEC-020은 견적 FE 적용안이며 배차는 별도 검토 대상이다.
- 요청 처리 중 생성·저장되는 정보: server `setty.dispatch` 계약에 있는 값과 운영자가 남기는 기록만 적는다.

## 현재 상태

동의 UI는 화면에만 있다. server `BuyerDispatchRequestCreateRequest`와 `SellerInputSubmitRequest`에
동의 여부·안내문 버전 필드가 없어 FE도 보내지 않는다. 동의 증적을 남기려면 BE 계약을 함께 확정해야 한다.

## 실제 사용자 접수 전 남은 확정 사항

- 배차의 수집 항목·이용 목적·보유 기간을 팀이 확정하고 DEC로 남긴다. 지금 값은 시안 문구다.
- `setty@example.com`을 실제로 수신·처리할 수 있는 팀 문의 채널로 바꾼다.
- 동의 증적 저장, 보유 기간 만료 삭제, 수동 철회 절차를 확정하고 통합 테스트한다.
- 요청·응답·오류 로그에 이름·연락처·받는 주소를 남기지 않는지 확인한다.

이 파일의 FE 완료는 실제 개인정보 접수 준비 전체가 완료됐다는 뜻이 아니다.
