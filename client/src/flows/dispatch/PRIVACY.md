# 개인정보 동의 안내 FE 경계

`개인정보 수집·이용 동의` 안내 화면(`screens/PrivacyConsentNoticeScreen.tsx`)이 안내하는 내용의 근거를 적는다.

## FE가 보장하는 것

- `(필수) 개인정보 수집·이용 동의`를 체크하지 않으면 요청을 전송하지 않는다.
- `보기`로 여는 안내 화면에서 처리 목적, 사용자 입력 항목, 요청 처리 중 생성·저장되는 정보,
  보유·이용 기간, 동의 거부, 철회·삭제 요청과 파기, 처리 주체와 문의, 안내문 적용일·버전을 안내한다.
- 안내 문구의 값은 `model/dispatchPrivacyPolicy.ts` 한곳에서 가져온다. 화면과 문구 파일에서 정책을 새로 만들지 않는다.

## 값의 출처

문장과 값은 PR #20에서 정리한 개인정보 처리 안내 전문(DEC-020 적용안)을 그대로 쓴다.
flow 경계 때문에 `flows/estimate`를 import하지 않고 같은 값을 `model/dispatchPrivacyPolicy.ts`에 둔다.
안내 문구를 바꿔야 하면 DEC-020을 먼저 갱신하고 두 flow의 값을 함께 맞춘다.

## 현재 상태

동의 UI는 화면에만 있다. server `BuyerDispatchRequestCreateRequest`와 `SellerInputSubmitRequest`에
동의 여부·안내문 버전 필드가 없어 FE도 보내지 않는다. 동의 증적을 남기려면 BE 계약을 함께 확정해야 한다.

## 실제 사용자 접수 전 남은 확정 사항

- DEC-020은 견적 FE 적용안이며 팀 합의가 아직 확인되지 않았다. 배차 요청에 그대로 적용할지 팀이 확정해야 한다.
- `setty@example.com`을 실제로 수신·처리할 수 있는 팀 문의 채널로 바꾼다.
- 동의 증적 저장, 보유 기간 만료 삭제, 수동 철회 절차를 확정하고 통합 테스트한다.
- 요청·응답·오류 로그에 이름·연락처를 남기지 않는지 확인한다.

이 파일의 FE 완료는 실제 개인정보 접수 준비 전체가 완료됐다는 뜻이 아니다.
