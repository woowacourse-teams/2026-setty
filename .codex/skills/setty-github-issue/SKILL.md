## 이슈 제목

모든 작업 Issue 제목은 정확히 `<type>: `으로 시작하고 하나만 선택한다. 그 뒤에 이슈 제목은 한글으로 적는다.

- `build`: 빌드 시스템 또는 외부 의존성 변경
- `ci`: CI 설정 또는 스크립트 변경
- `docs`: 문서만 변경
- `feat`: 사용자 또는 운영자에게 새 기능 제공
- `fix`: 버그 수정
- `perf`: 측정 가능한 성능 개선
- `refactor`: 기능 추가나 버그 수정이 아닌 코드 구조 변경
- `style`: 코드 의미에 영향을 주지 않는 서식·표현 변경
- `test`: 테스트 추가 또는 기존 테스트 수정만 수행

### 예시

- feat: 브라우저 탭과 홈 화면에 SETTY 로고 파비콘을 표시한다
- chore: 서비스 전반에서 토스페이스 이모지 폰트를 제거한다

## 영역 라벨

- 결과가 `client/**` 또는 클라이언트 관련 작업이면 `client` 라벨을 붙인다.
- 결과가 `server/**` 또는 서버 관련 작업이면 `server` 라벨을 붙인다.
- 결과가 앞선 두 영역과 관련이 없으면 라벨을 붙이지 않는다.
