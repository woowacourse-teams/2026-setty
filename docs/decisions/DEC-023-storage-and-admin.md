# DEC-023 DB·사진 저장·관리자 보호

- 상태: **부분 합의·검증 필요**
- 결정일: 2026-08-05
- 참여자: 캐리, 스마일, 밀란, 타스, 코코

## 합의된 방향

- 관계형 DB는 MySQL을 사용한다.
- 첫 MVP의 개발 스키마는 JPA `ddl-auto=update`로 관리한다. Flyway는 사용자 행동 검증 후 도입 여부를 재검토한다.
- 예상 견적 사진은 선택, 배차 요청 사진은 필수다.
- 사진 저장은 S3 방향이고 워크북 제안 최대 용량은 25MB다.
- 일반 사용자 회원가입은 없고 운영자 화면은 계정 없는 단일 진입 비밀번호 방식을 검토한다.

## 검토한 선택지

- 관계형 DB·외부 파일 저장·최소 관리자 보호
- 관계형 DB를 사용하되 첫 기능에서 사진 제외
- 가상 저장으로 인터페이스만 먼저 검증

## 기술 확인이 필요한 부분

- `팀내 공유`는 비밀정보 저장 방식이 아니다. 저장소에 커밋하지 않고 환경 변수 또는 승인된 비밀 저장소와 접근자를 정해야 한다.
- 단일 비밀번호는 서버에서 검증하고 세션·시도 제한·교체 방법을 가져야 한다. 프론트에 비밀번호를 포함하면 안 된다.
- S3 버킷 접근, 파일 형식·용량·삭제·비용을 확인해야 한다. 25MB는 확정 전 제안값이다.
- 사용자 링크 토큰과 만료 정책은 다음 배송 기능 Sprint 전 결정한다.

## 검증 계획

- 담당: 밀란, 견적·배차 백엔드 담당과 협업
- 기한: MySQL 연결은 공통 환경 완료 전, Flyway 도입 여부는 MVP 사용자 행동 검증 후, 인증·S3는 해당 기능 공개 전
- 막히는 작업: 실제 사진 업로드, 관리자 실데이터 접근, 배송 링크 구현
- 개발 차단: 가상 데이터 기반 MySQL 연결은 가능. 실제 인증·S3 기능은 검증 전 보류
- 사용자 공개 차단: 인증·비밀·사진 삭제 검증 전 관련 기능 공개 불가
- 재검토: 실제 레포·계정·비용·운영자가 확정될 때

## 연결·영향·대체

- 관련 문서: `docs/product/mvp-scope.md`, `server/AGENTS.md`, `client/AGENTS.md`
- 관련 Issue: 공통 환경, 견적 BE, 배차 BE1·BE2, 두 FE의 사진·관리자 화면
- 사용자 영향: 실제 사진·개인정보 접수 시 안전한 접근·삭제 필요
- 운영 영향: 단일 관리자 비밀의 공유·교체·복구 절차 필요
- 기술 영향: MySQL 스키마 자동 생성은 첫 MVP 개발 환경에 한정한다. Flyway 도입 여부는 사용자 행동 검증 후 결정하고, 인증·S3는 관련 기능과 공개 검증으로 분리한다.
- 대체: DB·스키마 도구가 모두 미정이던 초안
