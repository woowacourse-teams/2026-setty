# 결제 정책

결제 금액, 승인 결과와 환불을 정의한다. 주문의 만료와 취소 조건은 [주문·매물 정책](order.md)을 따른다.

## 상태 목록

- 결제: `UNKNOWN`, `DONE`, `CANCELED`(환불 완료).
- 환불: `REQUESTED`, `DONE`, `FAILED`. 결제와 따로 기록한다.
- 결제창 취소·명확한 승인 실패에는 이름 붙인 결제 상태값이 없다.

## 결제 금액

- 물품 가격과 예상 배송비를 합산하여 한 번에 온라인 결제한다.
- 실제 배송비는 예상 배송비와 같다. 배송비 차액은 발생하지 않는다.

```mermaid
flowchart LR
    I["물품 가격"] --> T["물품 가격 + 배송비<br/>한 번에 온라인 결제"]
    F["예상 배송비"] --> T
    F --> D["실제 배송비 = 예상 배송비<br/>차액 없음"]
```

## 승인·재시도

- 주문이 만료되거나 취소되기 전에 토스 승인 성공이 확인되면 결제를 `DONE`, 주문을 즉시 `CONFIRMED`로 확정한다.
- 주문 만료 또는 허용된 판매자 취소가 먼저 확정된 뒤 승인 성공이 확인되면 [주문 정책](order.md)에 따른 주문·매물 상태를 유지하고 결제 금액 전액을 환불한다.
- 배송 요청 생성은 주문 확정 이후 별도 흐름으로 처리한다. 배송 요청 생성이 실패해도 주문 확정을 되돌리지 않는다.
- 결제창 취소 또는 명확한 승인 실패 후에도 기존 주문을 원래 만료 시각까지 `PENDING`으로 유지한다. 만료 시각은 [주문·매물 정책](order.md#만료재결제)을 따른다.
- 같은 주문의 중복 승인 요청은 토스 승인 API 호출 전에 차단한다.

## 결과 미확정

- 결제 결과가 불명확하면 결제를 `UNKNOWN`으로 두고 같은 주문의 재결제를 차단한다.
- 결과가 불명확한 승인 요청에는 다른 결제 키 차단과 같은 `409 PAYMENT_IN_PROGRESS`(결과 확인 중)로 응답한다. 명확한 거절(`400 PAYMENT_CONFIRM_FAILED`)과 구분해 구매자가 "실패"로 오해하고 다시 결제하지 않게 한다. 이 상태에서 들어온 결제 실패 복귀는 무시한다.
- 그 밖의 후속 정책은 아직 정하지 않았다. 미정인 범위는 [확인 필요](#확인-필요)에 기록한다. 주문 만료 기준은 [주문·매물 정책](order.md#만료재결제)을 따르고, 만료 후 승인 성공이 확인됐을 때의 [환불 정책](#환불)은 유지한다.

```mermaid
flowchart TB
    P["주문 PENDING"] -->|"결제 시도"| G{"같은 주문의<br/>승인 요청 진행 중?"}
    G -->|"예"| B["추가 토스 승인 호출 차단"]
    G -->|"아니오"| T["토스 승인 요청"]
    T -->|"만료 전 승인 성공 확인"| C["결제 DONE<br/>주문 CONFIRMED"]
    T -->|"명확한 실패·결제창 취소"| P
    T -->|"결과 불명"| U["결제 UNKNOWN<br/>같은 주문 재결제 차단"]
    P -->|"주문 만료 시각 도달"| E["주문 EXPIRED"]
    T -->|"승인 응답 대기 중 주문 만료"| E
    U -->|"주문 만료 시각 도달"| E
    E -->|"뒤늦은 승인 성공 확인"| R["주문 EXPIRED 유지<br/>결제 금액 전액 환불"]
```

## 환불

- 환불은 주문 취소 확정 또는 만료 후 뒤늦게 확인된 승인에 의해 발생한다. 주문 취소 확정 이벤트를 받은 결제 영역은 해당 주문의 승인된 결제를 환불 대상으로 기록한다.
- 구매자 취소 확정 뒤 환불 대상 기록은 아직 구현되지 않았다([#602](https://github.com/woowacourse-teams/2026-setty/issues/602)). 지금 자동 환불은 주문 만료·판매자 취소 뒤 뒤늦게 확인된 승인에만 적용되고, 구매자 취소로 끝난 주문의 승인 결제는 [수동 확인 절차](../../server/docs/payment/expired-order-manual-refund.md)로 다룬다.
- 기록된 환불 대상은 배치에서 결제 취소를 처리한다. 결제 취소가 완료되면 구매자에게 결제 금액이 환불된다. 주문 취소 확정은 환불 완료를 뜻하지 않는다.
- 환불 배치는 5분마다 돈다. 응답을 받지 못했거나 일시 오류이면 같은 요청으로 다시 보내고, 5번 시도해도 끝나지 않거나 토스가 취소할 수 없다고 답하면 `FAILED`로 멈추고 운영자가 확인한다.
- 판매자 취소는 결제 전 주문에만 허용된다. 판매자 취소 확정 후 뒤늦게 결제 승인이 확인되면 승인 금액 전액을 환불한다.

```mermaid
flowchart LR
    O["주문 취소 확정"] --> R["승인 결제<br/>환불 대상 기록"]
    E["주문 만료 후 승인 성공 확인"] --> R
    S["판매자 취소 확정 후 승인 성공 확인"] --> R
    R --> B["결제 취소 배치"]
    B --> C["결제 취소 완료<br/>환불 완료"]
```

## 결제 상태 전이

표의 `—`는 현 정책에 이름 붙인 결제 상태값이 없는 단계다. 결제창 취소와 명확한 승인 실패에 대응하는 별도 상태값은 현 정책에 명시되지 않았다.

| 현재 결제 상태 | 조건 | 다음 결제 상태 | 결과 |
| --- | --- | --- | --- |
| `—` | 승인 성공 확인 | `DONE` | 주문이 유효하면 `CONFIRMED`, 만료·판매자 취소가 먼저 확정되었으면 전액 환불 대상 |
| `—` | 토스 승인 요청 직전 | `UNKNOWN` | 승인 결과를 확인할 때까지 같은 주문의 다른 결제 차단 |
| `UNKNOWN` | 명확한 승인 실패 또는 토스에 승인 없음 확인 | `—` | 주문은 원래 만료 시각까지 `PENDING` 유지 |
| `—` | 결제창 취소 또는 명확한 승인 실패 | `—` | 주문은 원래 만료 시각까지 `PENDING` 유지 |
| `UNKNOWN` | 최종 승인 성공 확인 | `DONE` | 주문의 만료·판매자 취소 여부에 따라 확정 또는 전액 환불 |
| `DONE` | 같은 주문의 승인 재요청 | `DONE` 유지 | 중복 승인 차단 |
| `DONE` | 환불 대상의 결제 취소 완료 | `CANCELED` | 환불 완료 |

승인 결제의 환불 대상 기록과 결제 취소 완료는 [환불](#환불)에서 정의한다.

## 확인 필요

- 결제 결과가 불명확한 상황(`UNKNOWN`)에서 주문 만료 후 동일 구매자의 신규 구매, 고객 표시, 결과 미확정이 오래 지속될 때의 처리 기준을 정해야 한다. 토스에 다시 물어 승인·미승인을 확인하는 정리는 10분이 지난 시도부터 5분마다 한다.
- 환불 진행·완료를 고객에게 어떻게 표시할지 정해야 한다.
