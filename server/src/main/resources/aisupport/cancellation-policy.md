# SETTY 구매자 취소 상담 정책
지식 버전: cancellation-knowledge-v2 / 대응 서버 판단: cancellation-read-v1
근거: docs/policy/order.md의 취소, docs/policy/delivery.md의 상태 전이,
docs/policy/payment.md의 환불 및 OrderSupportQuery의 현재 구현을 대조한 요약입니다.
정책이나 구현을 바꾸면 이 파일과 대화 평가도 함께 갱신합니다. 아래 내용은 일반 규칙이며 특정 주문의 최신 상태는 조회가 필요합니다.

## 취소 가능 여부
- 결제가 완료된 주문(CONFIRMED)에서 배송 요청이 없거나(ABSENT) 배차 대기(REQUESTED)이면 현재 취소 요청이 가능한 상태입니다. 서버 사유: BEFORE_DRIVER_ACCEPTANCE.
- 배송원이 배차를 수락한 뒤(ACCEPTED, DRIVER_ACCEPTED), 픽업한 뒤(PICKED_UP, ALREADY_PICKED_UP), 배송을 완료한 뒤(DELIVERED, ALREADY_DELIVERED)에는 현재 정책상 구매자 취소가 불가능합니다.
- 취소 대기(CANCEL_PENDING, CANCELLATION_PENDING)는 요청 처리 중이며 취소 완료가 아닙니다. 같은 요청을 반복할 필요가 없습니다.
- 취소 상태(CANCELLED, ALREADY_CANCELLED)는 이미 취소된 주문입니다. 환불 완료를 뜻하지 않습니다.
- 구매 확정(COMPLETED, PURCHASE_COMPLETED) 주문은 취소할 수 없습니다.
- 결제 대기(PENDING, PAYMENT_PENDING)는 결제 완료 주문의 취소 요청 대상이 아닙니다. 취소 대기와 다릅니다.
- 결제 승인 후 주문 확정 대기(PAID, ORDER_CONFIRMATION_PENDING)에는 구매자 취소 요청을 접수하지 않습니다. 주문 확정 뒤 현재 취소 가능 여부를 다시 확인할 수 있습니다.
- 결제 만료(EXPIRED, ORDER_EXPIRED)는 결제 대기 시간이 지나 만료된 주문입니다.
- 상태 불일치·조회 오류·알 수 없는 상태는 판단 불가(UNKNOWN)입니다. 취소 가능·불가능을 임의로 확정하지 않습니다.

## 요청과 결과의 구분
주문 상세 또는 상담의 활성 최종 확인 질문에 대화 또는 버튼으로 동의하여 구매자가 취소를 요청하면 먼저 취소 대기로 접수될 수 있습니다. 배송 영역이 실제 처리 시점의 상태를 확인한 뒤 최종 결과를 반영합니다.
배송 요청이 없거나 REQUESTED이면 취소가 확정될 수 있고, 수락 이후이면 거절되어 주문이 CONFIRMED로 돌아갈 수 있습니다.
상담의 ELIGIBLE은 조회 시점의 사전 확인입니다. 이후 기사 수락 등으로 결과가 달라질 수 있습니다.
현재 CONFIRMED라는 사실만으로 과거 취소 요청이 거절됐다고 판단할 수 없습니다. 현재 조회 도구에는 과거 거절 이력·사유가 없습니다.

## 환불과 현재 지원 범위
이 프로젝트는 실제 결제가 없는 테스트 서비스입니다. 주문 취소 확정과 결제 환불 완료는 별개입니다.
일반 정책 문서에는 환불 대상 기록과 배치 처리가 계획되어 있지만, 현재 상담은 환불 처리·진행 상태·완료 여부를 조회하거나 실행할 수 없습니다.
따라서 자동 환불이 실행되었다거나 언제 환불된다고 약속하지 않습니다.
현재 상담은 본인 주문 검색, 취소 가능 여부 안내, 대상 주문에 대한 명시적인 최종 동의 후 서버 취소 요청 접수를 제공합니다. 주문 확인의 '네'와 최종 취소 동의의 '네'는 다릅니다. 현재 최종 확인 질문에 명확히 동의한 대화 또는 버튼만 서버가 검증해 처리합니다. 질문·조건이 섞인 답변은 재확인합니다. 반품 접수, 상담원 연결, 배송원 연락·협의, 수수료를 내는 예외 취소는 지원하지 않습니다.
픽업 후 취소가 불가능할 때 지원하지 않는 절차를 대안으로 만들어내지 않습니다.
