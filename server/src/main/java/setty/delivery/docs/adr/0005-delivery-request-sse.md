# ADR-0005: 배송 요청 목록을 SSE 변경 신호로 갱신

## 상태

**채택**

## 맥락

기사 앱의 요청 목록은 새 배송 등록과 다른 기사의 수락으로 바뀐다. 주기적 HTTP 조회는 변경이 없을 때도 요청을 반복한다.

## 결정

**단일 서버의 메모리 `SseEmitter`로 `delivery-requests-changed` 신호를 전송한다.**

- 배송 저장 또는 수락 뒤 `DeliveryRequestsChanged`를 발행한다.
- `DeliveryRequestsChangedListener`는 커밋 뒤에만 SSE를 전송한다.
- 앱은 신호와 재연결 뒤 `GET /api/delivery/requests`를 다시 호출한다.
- 이벤트는 목록 데이터를 담지 않는다.
- 전송 실패는 경고 로그만 남기며 저장된 배송을 롤백하지 않는다.

## 결과

- 변경이 없을 때 반복 조회가 없다.
- 연결 상태는 단일 서버 메모리에만 존재한다. 다중 인스턴스 전환 시 공유 브로커 또는 별도 전달 경계가 필요하다.
- `AFTER_COMMIT` 예외는 외부 UI 알림에만 허용된다. Order 상태 동기화 규칙은 유지한다.

## 거부한 대안

- **Polling 유지: 거부.** 변경이 없어도 요청을 반복한다.
- **WebSocket: 보류.** 현재 요구는 서버→앱 단방향 신호뿐이다.

## 검증

- SSE 구독·변경 신호·연결 종료 정리를 단위 테스트한다.
- 배송 저장과 수락이 목록 변경 이벤트를 발행하는지 확인한다.
- 알림 전송 예외가 리스너 밖으로 전파되지 않는지 확인한다.
